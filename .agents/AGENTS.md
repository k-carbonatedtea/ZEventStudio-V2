# Workspace Customizations


## 国际化规范 (i18n)
- 所有用户可见文本（包括 UI 标签、菜单、按钮、提示信息 Toast、对话框、参数占位符与错误提示等）严禁硬编码，必须统一使用 `src/i18n` 系统。
- 新增或修改界面文本时，必须同步在 `src/i18n/locales.rs` 中补齐中英文对应键值。
- 在 UI 组件与渲染逻辑中统一通过 `state.t("section.key")` 或 `crate::i18n::t("section.key", state.lang)` 进行文案渲染，保证多语言键名结构严格对称。

## 通用行为规则
- 优先选择局部编辑（`replace_file_content` 或 `multi_replace_file_content`）而非重写整个文件（`write_to_file`）。
- 除非文件被编辑过或内容可能发生改变，否则不要重复阅读已经读取过的文件。
- 与用户的输出交流追求简洁，但内部推理过程（thoughts）必须详尽。

## 代码规范
- 统一代码风格：所有代码风格保持高度一致。
- 单个文件不超过 400 行，如果超过请进行拆分。
- 代码嵌套层级不超过 4 层。
- 编写代码时必须包含中文注释。

## 构建与调试规范
  - 修改代码时后，进行编译校验。
