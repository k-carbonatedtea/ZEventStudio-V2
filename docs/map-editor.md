# BOTW 地图编辑器

在设置中配置对应平台的游戏资源目录，然后从文件树或“文件 → 打开”打开 `.smubin` / `.mubin`。支持磁盘文件和 SARC/Pack 内的地图条目，也可以把文件路径作为程序启动参数。资源解析在后台执行，首次打开较大的地图需要等待。

## 场景与资源

- 根据 ActorInfo 的 `bfres`、`mainModel` 选择对象子模型，自动搜索 `-00`、`-01` 等分包；缺少 ActorInfo 模型配置时读取 Actor Pack 中的 ModelList。
- 读取材质的着色器采样器映射、纹理数组层、UV 变换和正反面设置，避免把法线或遮罩显示成颜色。岩壁共享地形纹理数组。
- 按对象的位置、XYZ 欧拉旋转、非均匀缩放绘制实例。共享同一模型的对象复用几何与纹理。UMii NPC 使用现有 UMii 部件合成功能。
- 自动显示同一区域的 Static/Dynamic 配套地图。配套对象作为只读背景；点击顶部“配套地图”可切换到对应文件编辑。保存只写回当前标签对应的文件。
- 神庙额外加载 Pack 中的 `DgnMrgPrt_Dungeon*.sbfres` 合并建筑及配套纹理，作为只读背景。
- 地形读取 TSCB、256×256 高度与材质数据，水面单独读取 64×64 高度。当前区域使用最小 250 米的地形瓦片；裁掉被更细瓦片覆盖的粗瓦片部分。
- Switch 的 `Terrain.Tex.sbfres` / `Terrain.Tex1.sbfres` 可直接解码，包含 88 个材质编号到 83 个纹理层的映射。也支持 `MaterialAlb_*.png` 缓存作为解码失败时的回退：环境变量 `ZEVENT_TERRAIN_CACHE`、项目的 `Terrain/Materials`，或程序工作目录的 `.cache/map_terrain`。
- 地形保留原生 1024×1024 材质数组，由 GPU 按 256×256 材质控制图混合并重复采样；自动生成 mipmap，并使用 8 倍各向异性过滤。近景不再把整块 250 米地形压进一张 512×512 烘焙图。软件渲染回退仍使用低分辨率缩略纹理。
- 逻辑对象沿用 Rito 的方向立方体贴图（LinkTag/EventTag 按类型着色并显示方向字母），普通无模型对象使用 Rito TexturedCube；区域保留低透明填充和黑色线框，支持 Box、Sphere、Cylinder。默认只展开选中对象和一跳关联，避免全部标记覆盖场景。资源缺失会在对象列表和属性栏显示诊断。隐藏对象透视框默认关闭，关闭时区域网格遵守地形深度；开启后作为置顶辅助线。

## 操作

地图工作区采用三栏布局：左侧对象大纲，中间场景，右侧属性。拖动两侧分隔条调整宽度；原项目文件树收进左侧“项目资源”折叠区。对象列表采用虚拟滚动，支持当前、配套、全部三个范围，以及 Actor 名称和 HashId 搜索。

底部“资产”面板按 ActorInfo 的 Profile 分类浏览游戏资产，支持中文名称、Actor ID、Profile 和模型名称搜索，也可切换网格/列表、收藏常用资产。选中条目会在详情栏异步显示实际模型预览；目录和网格不预先解码全部模型。将资产拖到视口可直接放置，或双击资产/点“放置到地图”后点击场景表面；“添加到视图中心”可直接在当前视图中心创建对象。放置会命中最近的可见模型或地形表面，空白处使用相机目标高度。新对象使用唯一 HashId，不复制源对象链接；新增操作可撤销、重做并保存。需要模型的资产按需在后台加载并合并到当前场景，保留地图、地形和相机状态；纯逻辑资产继续使用编辑器标记显示。收藏保存在 `%LOCALAPPDATA%\Zevent\asset-browser.json`。

顶部提供三种视图：

| 视图 | 显示方式 |
| --- | --- |
| 游戏视图 | 收起无模型辅助对象和连线，保留静态场景预览 |
| 上下文（默认） | 展开选中对象及直接传入、传出的一跳关联，默认只画相关链接 |
| 诊断 | 展开全部辅助对象与已解析链接，仍遵守分类、单对象隐藏和图层设置 |

“可见对象”控制有模型的对象，“全部辅助对象”展开区域与逻辑标记；在游戏视图手动开启辅助对象或链接，会切回上下文视图。切换视图会关闭透视辅助线。左侧每行的复选框可单独隐藏对象，显式隐藏及关闭配套图层优先于选中状态。工具区还提供地图模型、配套地图、地形、水体、对象链接和仅选中对象链接开关。显隐只影响编辑器，不写入地图文件。配套对象可选中、聚焦和查看属性，也可以从属性栏打开所属地图编辑。

大纲可按地图对象、镜头、事件、天气、音频、物理和外部系统筛选；筛选同时包含指向该类别的连接器及参数引用对象。通用 LinkTagAnd/Or 不会因为连接某个系统而被重新归类。列表和属性栏显示编辑器中的可见状态及隐藏原因；这不代表对象是否处于相机范围内或被地形遮挡。

右侧属性按“变换、Obj / 对象、参数、传入链接、传出链接”分组，可独立折叠：

- 位置、旋转和缩放使用 XYZ 同行输入；旋转显示角度。
- Obj 展示基础字段及未知扩展字段，参数支持 Bool、Float、Int、Uint、String、Double、Long、ULong、Map、Array 和 Null。可添加、改名和删除扩展属性；嵌套 Map / Array 可展开编辑。整数与浮点保留原始 BYML 类型；越界或非有限数值会保留草稿并报错，按 Esc 可取消。
- 参数可通过剪贴板复制和粘贴 BYML YAML，保留类型。修改 UnitConfigName 后重新解析模型。
- 传入、传出链接包含当前和配套地图，按目标类别分组计数，并标明分类依据：Actor Profile、名称推断、对象参数或链接类型推断。点击已解析目标可跳转聚焦。传出链接支持添加、修改类型和目标、展开编辑嵌套参数以及删除；每条链接的参数编辑区默认收起，可从 Rito 的链接类型列表选择，也可输入自定义类型。目标 HashId 支持十进制及 `0x` 十六进制；未解析的原有链接会保留并标记“可能位于其他地图”，不会直接认定为全局系统。
- “系统引用 / 参数绑定”独立列出事件流程及入口、镜头预设、天气和音频等已识别参数。这里读取具体参数值，不等于验证了游戏运行时绑定，也不替代 `LinksToObj`。
- 链接按类别使用颜色和形状辅助区分，镜头为虚线、天气为点线，外部或未知引用为虚线；普通链接为低透明度细线，选中关系高亮。有真实坐标的镜头、事件、天气对象仍连到地图中的位置；选中对象的参数引用及未解析链接按类别汇总到视口右侧，并分别显示引用数与待解析数。完整名称、HashId 和依据可在属性栏查看。未解析链接只在选中其源对象时展开，避免诊断视图出现大量悬空线。链接跟随源、目标对象的显隐与配套图层设置。

编辑和保存前会校验必需字段、HashId 唯一性及新链接目标。修改 HashId 会同步更新当前文件内的入链；如果配套地图有入链，则阻止单独修改 HashId 或删除该对象。配套文件保持只读，不会被连带保存。新增属性、链接与参数粘贴均支持撤销和重做。

| 操作 | 方法 |
| --- | --- |
| 选中对象 | 左键点击实际模型，或从左侧列表选择 |
| 搜索 | 输入 Actor 名称或十六进制 HashId |
| 旋转视角 | 右键拖动，或 Alt+左键拖动 |
| 平移视角 | 中键拖动 |
| 缩放视角 | 滚轮 |
| 聚焦对象 | `F` 或双击列表对象 |
| 移动对象 | 选中后 Shift+左键拖动，在当前高度的 XZ 平面移动 |
| 精确变换 | 右侧输入位置、旋转角度或缩放，按 Enter 应用；Esc 取消输入 |
| 吸附 | “吸附到地形”将对象原点放到高度场表面 |
| 复制 / 删除 | `Ctrl+D` / `Delete`，或属性栏按钮 |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z`，最多 100 步 |
| 保存 | `Ctrl+S` 或顶部保存按钮 |
| 放置资产 | 底部“资产”面板拖入视口，或选择资产后双击并点击目标位置；`Esc` 取消待放置状态 |

保存保留 BYML 版本、端序、Yaz0 压缩状态、未知字段和 Rails 数据。变换后清零 SRTHash；复制生成唯一 HashId；删除清理当前文件内指向被删除对象的连线。SARC 内的文件通过现有归档写入器回写。

## 加载与视口性能

资源查找、SARC 索引与 BFRES 解析在一次加载内复用；仅并行解码当前显示材质使用的颜色纹理，跳过本预览着色器未使用的法线和遮罩。BNTX 优先读取原生纹理指针表。地图标签共享最近使用的已解码地形数组，重新加载时检查源文件的长度和修改时间。

视口在独立线程渲染，快速拖动时保留最新待处理请求，避免输入积压。相机变化复用 GPU 绘制命令，只更新相机矩阵；编辑、撤销、选择、可见性或资源变化会使相应缓存失效。链接分类及系统引用分析按地图与资源缓存，选择和显隐切换仅更新关联范围。属性折叠区及链接嵌套参数按展开状态构建。场景快照共享几何和纹理，静止地图停止持续重绘。点击拾取、选择框、透视辅助线及链接投影统一使用当前已显示帧的相机。

2026-11-02，本机 RTX 5080 / Vulkan、开发构建、F-5 Dynamic（含配套地图，782 网格、5,153,629 三角形），相同 1766×1172 渲染尺寸的实测：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 地图资源加载 | 50.2 秒 | 5.9 秒 |
| 解码并保留的场景纹理 | 1725 | 673 |
| 旋转时渲染及图像读回耗时，中位数 | 23.59 毫秒 | 3.72 毫秒 |
| 旋转时渲染及图像读回耗时，12 帧最大值 | 31.37 毫秒 | 5.29 毫秒 |
| 首帧 GPU 准备、渲染及读回 | 0.74 秒 | 0.94 秒 |

原生地形提高了首帧纹理上传量。以上单帧耗时包含离屏 GPU 渲染与 CPU 读回，不等同于软件界面 FPS；未清空操作系统磁盘缓存，也不代表所有地图和显卡的性能。GPUI 仍通过图像接收离屏结果，尚未实现直接共享 GPU 纹理。

## 当前范围

这是对象放置与静态场景预览功能。地形高度编辑、Rails 控制点编辑、游戏运行时动画、完整材质着色器、UMii 面部与体型动态变形尚未实现。水面使用简化材质。神庙中缺少独立模型的建筑由合并背景显示；修改这些对象的放置数据不会重建合并模型、碰撞或导航数据。Wii U 地图的读写保留大端格式，但其 BFRES/FTEX 显示能力受现有解析器限制，未达到 Switch 的验证范围。
